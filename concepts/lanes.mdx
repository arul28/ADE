A **lane** is ADE's name for a git worktree: an isolated branch and working copy for one piece of work, usually under `.ade/worktrees/<lane-name>/`. It is the unit of parallel work.

Because the lane is a real worktree, agents can run in the same repository at the same time without writing over each other or over your primary checkout. There is no stashing and no branch juggling.

## What a lane owns

- A **branch** and a working directory.
- The **chats, terminals, and CLI sessions** started in it.
- Its **diff**, file changes, test runs, and proof artifacts.
- The **pull request** created from it.

Everything in ADE is scoped to a lane, which is what makes "what is running, where, and why" answerable.

## One task, one lane

Create a lane from your default branch when you start something new. If the work grows, split it into a second lane, or stack one on top of the other.

A lane starts from a branch and inherits the repository. ADE records its base so it can rebase, restack, and show divergence later.

## Stacking

Stacking puts a lane on top of another lane instead of on `main`. Use it when a piece of work depends on unmerged work: the child branch contains the parent's commits, and the graph shows the order.

## Environment

A lane can carry setup steps that run when it is created or resumed — install dependencies, copy env files, start a service. That keeps a fresh worktree usable without manual setup.

<Card title="Lane environment" icon="sliders" href="/lanes/environment" horizontal>
  Setup scripts, environment files, and per-lane configuration.
</Card>

## Finishing a lane

When the work is merged, archive the lane: ADE removes the worktree, and you choose whether to delete the branch. Archive rather than delete when you want the history and sessions to remain searchable.
