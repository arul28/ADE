- Out of hours or blocked: the run fails cleanly and the person is told (like the cancelled timed-wake email).
- Sign-ins: a provider sign-in that expires mid-run with nobody there to renew it; fail and notify, never prompt on the cloud computer.
- Secrets: rule secrets and webhook signing secrets must reach the computer safely (signing secrets never reach the relay today).
- Results: run history, notifications and PRs must reach the person's other computers and phone; GitHub credential on the cloud computer.
- CLI-session runs: depend on the CLI-on-cloud work above (one launch flow).
- Hidden ADE Cloud: "Run on ADE Cloud" must stay hidden for accounts without access.

### 1. iOS simulator pool: one shared, warm Mac that streams only simulators (side chat research, 2026-11-11)

- **Idea:** a macOS VM per user means one Mac serves only 2 users (Apple allows 2 VMs per Mac). Instead, run many iOS simulators on one Mac, in one macOS install, and stream only each user's simulator screen with ADE's own simulator streaming (`ade apple` / sim helper). Builds are short bursts that wait a few seconds in a queue. One box serves many users at once, so buying Macs in bulk becomes worth it.
- **How many fit:** a running simulator uses about 1.3 to 4 GB. One developer ran 14 at once on a 16 GB M1 mini; simslim (turns off background services) claims 19 on 16 GB. Plan on about 5 per 16 GB as stock. A 14-core M4 Pro takes about 2 to 3 warm builds at once (30 to 60 s each).
- **Box to pick:** Mac mini M4 Pro, 64 GB, 1 to 2 TB disk. About 12 to 25 simulators at once (an estimate, NOT measured).
- **Costs:**
  - Buy: about $2,000 (older launch price) plus hosting (hosting price not found).
  - Rent monthly: MacWeb M4 Pro 64 GB 1 TB, $299 a month, no upfront.
  - AWS mac-m4pro.metal 48 GB: $1.97 an hour, $47 a day, 24-hour minimum.
  - Per simulator-hour, at about 15 users at once and 40% busy: owned about $0.03, MacWeb about $0.07, AWS about $0.33.
  - Suggested: an iOS simulator size at about 10x ADE hours; about 40 to 60 subscribers per box.
- **Catches:**
  - (a) Security: builds run the user's code. Without a VM per user, each person needs their own macOS user account, locked-down permissions and a wipe between sessions. Fine for paying, signed-in users; risky for free ones.
  - (b) Apple license gray area: macOS allows leasing only for "Permitted Developer Services" (builds, automated testing), with a 24-hour minimum, and Xcode's agreement reads as internal use. GitHub, Codemagic and Bitrise build other people's apps every day; an Apple forum question about remote simulators for others went unanswered. A lawyer is needed before charging.
  - (c) Reliability: simulators leak memory (one Apple forum post saw a simulator grow to 25 GB), CoreSim hangs, and per-account process and file limits cap you at about 9 to 10 simulators unless raised. Needs health checks and restarts.
  - (d) Several Xcode versions per box.
- **Next step proposed:** a pilot. Rent one MacWeb M4 Pro 64 GB for a month ($299) or one AWS M4 Pro for a day ($47), measure simulators plus builds at once with ADE's streaming, and get the lawyer's read.
