## `createAdeChat(options)`

```ts
function createAdeChat(options: CreateAdeChatOptions): Promise<AdeChatClient>
```

| Option | Type | |
|---|---|---|
| `home` | `string` | Required. Isolated state root. Created if missing. |
| `binaryPath` | `string` | Pin an `ade` binary. Skips every later resolution step. |
| `runtimeNodeModules` | `string` | `ADE_RUNTIME_NODE_MODULES`. Required with `binaryPath` when the native modules are not beside the binary. |
| `runtimeRoot` | `string` | `ADE_RUNTIME_ROOT`. Defaults to the parent of `runtimeNodeModules`. |
| `allowDownload` | `boolean` | Default `true`. `false` throws `runtime_unavailable` instead of reaching the network. |
| `channel` | `string` | Downloader channel: `latest` (default) or a release tag. |
| `logger` | `(line: string) => void` | Sidecar / client log sink. |
| `instructions` | `string \| { mode, text }` | Default instructions for every thread. A per-thread value replaces it. |
| `mcpHeaders` | `(key, serverName) => Record<string, string> \| undefined \| Promise<…>` | Supplies MCP header values at every create, resume, recreate and restart, and before each turn of a thread with remote servers (a changed value is pushed before the turn). May be async. Header values are never stored. See [MCP](/sdk/mcp#credentials-that-change). |
| `autoRestart` | `boolean \| { maxAttempts?, backoffMs? }` | Default off. Respawns the runtime after an unexpected exit and re-opens every live thread. `true` = 5 attempts, 1 s backoff that doubles. |
| `requireCompatibleRuntime` | `boolean` | Default off. `true` throws `runtime_incompatible` for a runtime outside `SUPPORTED_RUNTIME_RANGE`. |
| `source` | `"packaged"` | Set by `resolvePackagedRuntime()`. Makes `doctor().runtime.source` report `packaged`. |

`resolvePackagedRuntime(resourcesPath, { dir?, platform?, arch? })` returns `{ binaryPath, runtimeRoot, runtimeNodeModules, source: "packaged" }` or `null`. Spread it into the options. See [Bundling](/sdk/bundling#inside-a-packaged-app).

`SUPPORTED_RUNTIME_RANGE` is the runtime range this SDK build supports. See [Version compatibility](/sdk/runtime#version-compatibility) for each SDK version's range.

Runtime resolution runs in five steps: `binaryPath`, then an installed `@ade-dev/runtime-<target>` package, then the home cache, then `ade` on `PATH`, then a download. See [Bundling](/sdk/bundling).

## `threads.open` options

| Option | |
|---|---|
| `provider` | Any provider id present in the runtime model catalog; known provider ids are suggestions, not a closed set. |
| `model` | Catalog id (aliases resolved by the runtime). |
| `budget` | `{ maxTokens?, maxCostUsd? }`. Cumulative per-thread limit; stored with the key and enforced only when the runtime/provider reports the corresponding usage. |
| `permissionMode` | Provider-native permission mode, checked against provider capabilities when available. |
| `reasoningEffort` / `fastMode` | Provider-native reasoning tier and fast-mode flag, checked against provider capabilities when available. |
| `account` / `credential` / `preset` | Provider account instance, stored credential, or endpoint preset id. Create-only and persisted for recreation. |
| `permissions` | `"always-allow"` \| `"default"` \| `ThreadPermissionPolicy`. See [Permissions](/sdk/permissions). |
| `instructions` | `string \| { mode: "append" \| "replace", text }`. A bare string means append. |
| `cwd` | Absolute path the provider runs in. Created at mode `0755`. Defaults to `<home>/personal-chats/workspaces`. |
| `attachmentRoots` | `string[]`. Extra directories an absolute attachment path may point into. Same rules as `cwd`; at most 32. Runtime 1.2.82 or later. One refused entry fails the whole open, so test a candidate with `checkAttachmentRoot` or prepare the list with `filterAttachmentRoots` (SDK 0.5). See [Attachments](/sdk/threads#where-a-path-may-point). SDK 0.4. |
| `settingSources` | `"none"` (default) \| `"project"` \| `"user"` \| `"all"`. |
| `title` | Display title stored on the thread record. |
| `mcpServers` | Caller-owned servers for this thread. See [MCP](/sdk/mcp). |
| `loadUserMcpServers` | Opt the user's MCP back in. Explicit `false` ≠ omitting the field. |
| `refresh` | `{ mcpServers?, attachmentRoots? }`. Replaces the thread's MCP servers or attachment roots on a resume, so a new token, port or folder takes effect. The one option a resume does not ignore. A map or list identical to the one already in use is not sent again, so a host that repeats its own values costs no update call. |

Host configuration and provider launch choices persist on the thread record, so a resume that has to recreate a lost session rebuilds the same thread.

They apply on **create only**, with one exception: `refresh`. A resume reads `cwd`, `attachmentRoots`, `instructions`, `settingSources`, `permissions`, `permissionMode`, `reasoningEffort`, `fastMode`, `account`, `credential`, `preset`, `mcpServers` and `loadUserMcpServers` off the stored record and ignores what this call passed, logging one line per differing option. Open a different key to run under different configuration.

A **recreate** (the key is stored, but the runtime lost its session) uses the stored record first. This call's options fill only fields the record does not have. The SDK logs one line for each stored value it used.

```ts
type ThreadPermissionPolicy = {
  allowedTools?: string[];          // exact names, or a trailing `*`
  deniedTools?: string[];           // wins over allowedTools
  autoApproveMcpServers?: string[]; // same as `mcp:<server>:*`
  sandboxRoot?: string;             // absolute; containment, not a working dir
  fallback: "ask" | "deny";         // required
};
```

What a policy is worth depends on the provider and, on Claude, on `fallback`. A deny fallback removes the unnamed mutating built-ins and scopes MCP to the servers the policy names. An ask fallback relies on the Agent SDK's permission prompt. Read `thread.permissionCapability` and see [Permissions](/sdk/permissions).

## `pickDefaultModel` {#pickdefaultmodel}

```ts
function pickDefaultModel(
  models: readonly ModelCatalogEntry[],
  opts?: {
    available?: boolean;
    providers?: readonly string[];
    prefer?: (model: ModelCatalogEntry) => number;
  },
): ModelCatalogEntry | null
```

`available` (default `true`) keeps only models with `isAvailable` and `connected`. `providers` keeps only those providers and tries them in order. Within a provider, or within all of them when `providers` is absent, the catalog's `isDefault` model wins, then the first model the catalog lists. `client.models.defaultModel(opts)` is the same rule on a fresh catalog.

`prefer` (SDK 0.5) is your own ordering inside one provider's qualifying models. Return a number greater than zero to prefer a model: the highest score wins. Return 0 or less for "no opinion", and that model is ranked the usual way. A model nobody scores falls back to `isDefault`, then to catalog order, so `prefer` never removes a model from the pool. Use it to state a cost or family preference instead of keeping your own copy of the rule:

```ts
// Start new chats on the newest Sonnet, not on the provider's most
// expensive default.
const start = await ade.models.defaultModel({
  prefer: (model) => (/sonnet/i.test(model.id) ? 1 : 0),
});
```

`isSupportedProvider(value)` narrows a string such as `ModelCatalogEntry.provider` to `AdeProvider` without a cast. `ModelCatalogEntry.provider` is deliberately typed open, because a downloaded catalog can name a provider newer than this SDK.

## `checkAttachmentRoot` and `filterAttachmentRoots` {#attachment-root-helpers}

Both are SDK 0.5. They answer the question "will the runtime accept this root?" before you send it, because one refused entry fails the whole `threads.open`.

```ts
function checkAttachmentRoot(
  value: unknown,
  sdkHome: string,
): { ok: true; root: string } | { ok: false; reason: string };

function filterAttachmentRoots(
  value: unknown,
  sdkHome: string,
): { roots: string[]; dropped: Array<{ root: string; reason: string }> };
```

`checkAttachmentRoot` never throws. `ok: true` carries the canonical spelling the runtime will accept — the same one `threads.open` stores — so pass that, not your original string. `sdkHome` is the same `home` you give `createAdeChat`.

`filterAttachmentRoots` keeps every valid entry in list order, canonicalized and de-duplicated, capped at 32, and reports each refused or over-the-limit entry with its reason. Its `roots` is safe to pass straight to `threads.open`, so one bad entry no longer locks every chat:

```ts
const { roots, dropped } = filterAttachmentRoots([downloads, musicDir, "/"], home);
for (const entry of dropped) log.warn(`attachment root ignored: ${entry.root} — ${entry.reason}`);
await ade.threads.open("main", { ...createOptions, attachmentRoots: roots });
```

A non-array argument still throws `invalid_option`: that is a programming error, not a root you meant to filter.

## `doctor()` {#doctor}

```ts
type DoctorReport = {
  ok: boolean;
  sdkVersion: string;
  binary: {
    path: string;
    version: string | null;
    source: "option" | "path" | "download" | "cache";
    checksumVerified: boolean;
  };
  runtime: {
    source:
      | "packaged"
      | "explicit"
      | "bundled-package"
      | "cached-download"
      | "path"
      | "downloaded"
      | "attached";
    binaryPath: string;
    version: string | null;
    runtimeRoot: string | null;
    nodeModulesPath: string | null;
    signature: { signed: boolean; authority?: string; accepted?: boolean | null } | null;
    downloadedThisSession: boolean;
    checksumVerified: boolean;
    compatibility: {
      supported: boolean;
      range: string;          // SUPPORTED_RUNTIME_RANGE
      version: string | null; // what the runtime reported
      note: string | null;    // why a version passed without a check
    };
  };
  socket: {
    path: string;
    connected: boolean;
    runtimeVersion: string | null;
    pid: number | null;
  };
  events: {
    mode: "push" | "drain" | "unavailable";
    epoch: string | null;
    gapsRecovered: number;
  };
  providers: Record<string, ProviderStatus>;
  logins: {
    mode: "isolated" | "machine" | "attached";
    perProvider: Record<string, "isolated" | "shared" | "unknown">;
  };
  threads: { tracked: number; live: number };
  recentErrors: Array<{ at: string; scope: string; message: string }>;
};
```

`sdkVersion` is injected at package build time from `package.json`. Compare it to `socket.runtimeVersion` when versions disagree.

`binary` is the 0.1.x view and keeps its four `source` values. A `packaged` or `attached` runtime reports `binary.source: "option"`. `runtime` is the 0.2 view: which of the five resolution steps produced the binary, and what the OS thinks of its signature. `runtime.signature` is `null` for "not known", never for "not signed" — see [Runtime](/sdk/runtime#doctorruntime). `accepted` is Gatekeeper's verdict on the outermost `.app` that contains the runtime, and `null` when it could not be judged. `runtime.compatibility` compares the runtime version with `SUPPORTED_RUNTIME_RANGE`; see [Runtime](/sdk/runtime#version-compatibility).

## Errors

`AdeError` with `code`:

`runtime_incompatible` · `binary_not_found` · `download_failed` · `checksum_mismatch` · `spawn_failed` · `connect_failed` · `handshake_failed` · `rpc_error` · `rpc_timeout` · `transport_closed` · `protocol_error` · `thread_not_found` · `invalid_option` · `invalid_output` · `runtime_unavailable` · `approval_not_found` · `unauthorized` · `disposed` · `turn_in_flight` · `unsupported` · `sign_in_failed`

`turn_in_flight` (SDK 0.4) is every refusal that exists only because a turn is running: `setModel` or a reasoning `update` without `{ force: true }`, and a runtime action that must wait for the turn to end. Nothing changed; wait for the turn to finish, or call `interrupt()`, then call again. Before 0.4 these used `invalid_option`.

`unsupported` (SDK 0.4): the provider or the runtime cannot do what you asked. `retry()` and `editLast()` throw it for a provider other than Claude or Codex, and on a runtime without the `rerunLastTurn` action.

A relative or refused `cwd` throws `invalid_option`. So does a bad `attachmentRoots` entry, a policy with no `fallback`, a `sandboxRoot` that is not absolute, and an `approve()` naming a question-shaped request — the SDK checks those before any RPC, and the engine's own `invalid_argument:` refusals are mapped onto the same code. Prepare an `attachmentRoots` list with [`filterAttachmentRoots`](#attachment-root-helpers) to keep one bad entry from failing the open.

`runtime_incompatible` comes from `createAdeChat({ requireCompatibleRuntime: true })` when the runtime version is outside `SUPPORTED_RUNTIME_RANGE`.

`invalid_output` is thrown by `client.run()` after the structured response fails JSON parsing or schema validation twice. `InvalidOutputError.rawText` contains the last model response. `client.run()` rejects with `rpc_timeout` when a turn outlasts `timeoutMs` (default 10 minutes), and with `unsupported` when the turn asks for an approval or an answer, which a one-shot run cannot give.

`sign_in_failed` rejects a sign-in handle's `done` when the sign-in failed, was cancelled, or expired; the handle's last status names which.

`approve()` throws `approval_not_found` when the item is already settled. `unauthorized` comes from an Electron bridge whose `authorize` hook refused the call.

## MCP capability

See [MCP servers](/sdk/mcp). Shape:

```ts
type McpCapabilityReport = {
  strictRequested: boolean;
  level: "enforced" | "best-effort" | "unsupported";
  residual: string | null;
  mechanism: string;
  delivered: boolean;
};
```
